# gta11 R3F/Vite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver `gta11` as a pnpm-managed Vite + React + TypeScript game with React Three Fiber as the only WebGL renderer and frame-loop owner, preserving the existing gameplay simulation and assets.

**Architecture:** React mounts an R3F `<Canvas>` plus game overlays. `GameRuntime` constructs the existing `World` with R3F-provided renderer, camera, and canvas, then advances the simulation from `useFrame`. The simulation retains Cannon, asset parsing, entities, controls, and scenarios while a React UI bridge replaces imperative DOM bootstrap and UI mutation.

**Tech Stack:** pnpm 12.3.4, Vite 7.0.2, React 19.3.0, TypeScript 6.1.1, Three 0.186.0, @react-three/fiber 9.7.0, @react-three/postprocessing 3.1.1, Leva 0.10.1, Vitest 5.0.0, Testing Library 16.3.3, jsdom 30.0.1.

**Spec:** `docs/superpowers/specs/2026-09-09-gta11-r3f-vite-design.md`

## Global Constraints

- Preserve the existing game world, Cannon physics, characters, vehicles, controls, scenarios, and GLB assets; do not redesign gameplay.
- Use pnpm only; regenerate `pnpm-lock.yaml` from the versions listed above and remove `package-lock.json`.
- Use Vite's conventional React TypeScript entry points and make R3F the sole owner of WebGL canvas lifecycle, resize behavior, renderer configuration, and animation frames.
- `World` must never create a renderer, append a canvas, register a resize listener, or call `requestAnimationFrame` in externally managed mode.
- Expose all user-facing branding as `gta11`; do not leave visible `Sketchbook` copy.
- Asset and runtime errors must render a useful React overlay; unmounting must remove listeners and release runtime-owned resources.
- Every behavior change follows red-green-refactor. Run typecheck, unit tests, production build, and browser smoke verification before the final commit.

- [ ] **Step 4: Implement GameRuntime with R3F hooks**

```tsx
export function GameRuntime({ worldScenePath, onWorldReady, createWorld = createGameWorld }: Props) {
  const { gl, camera } = useThree();
  const worldRef = useRef<World>();
  useEffect(() => {
    const world = createWorld({ worldScenePath, runtime: { renderer: gl, camera: camera as THREE.PerspectiveCamera, canvas: gl.domElement } });
    worldRef.current = world;
    onWorldReady?.(world);
    return () => world.dispose();
  }, [gl, camera, worldScenePath, createWorld, onWorldReady]);
  useFrame((_, delta) => worldRef.current?.tick(delta));
  return null;
}
```

Ensure R3F owns rendering by never calling `renderer.render`, `composer.render`, `setSize`, or `requestAnimationFrame` from the injected branch. Configure `<Canvas shadows dpr={[1, 2]} gl={{ antialias: false }} camera={{ fov: 80, near: 0.1, far: 1010 }} />` in `App` and set ACES tone mapping through R3F-supported renderer configuration.
